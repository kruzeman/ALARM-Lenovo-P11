# USB-C OTG (режим хоста) — состояние на 10.11.2026

Цель: воткнутый в порт USB Wi-Fi адаптер должен определиться.

Что работает:
- DTS платы (`sm6115p-lenovo-j606f-hx83102p.dts` — нужен именно этот вариант; базовый
  `sm6115p-lenovo-j606f.dts` без `usb-role-switch` и без панели Himax) уже связывает FUSB302 на
  `i2c0 0x22` с `usb_dwc3` через role switch, `dr_mode = "otg"`, только high speed.
- Запись `host` в `/sys/class/usb_role/4e00000.usb-role-switch/role` действительно поднимает xHCI:
  появляются корневые хабы `usb1`/`usb2`, в `/sys/bus/usb/devices/` видны обе шины.

**Режим хоста работает (подтверждено 10.11.2026).** Достаточно вставить устройство — без ручного переключения роли
TCPM замечает подключение, переводит порт в host и включает VBUS: GPIO 38 становится `out high`, xHCI видит
устройство, и адаптер появляется в `/sys/bus/usb/devices/`:

```
usb 1-1: new high-speed USB device number 2 using xhci-hcd
usb 1-1: New USB device found, idVendor=0bda, idProduct=8179
usb 1-1: Product: 802.11n NIC
```

`/sys/class/usb_role/*/role` = `host`, `GPIO38` = `out high`. Для конкретно этого адаптера не хватает только
драйвера: `rtl8xxxu` в этом ядре не собран (`CONFIG_RTL8XXXU` не задан), поэтому `wlan1` не появляется. Если адаптер
нужен — достаточно собрать его модулем, больше ничего не требуется.

Заметки по неудачным попыткам (не повторять):
- Принудительная запись `role=host` поднимает xHCI, но VBUS остаётся выключенным, пока устройство реально не
  вставлено — регулятором владеет TCPM. `power_role` уже `source`; запись возвращает `EIO`; `i2cget` по `0x22`
  падает с `Device or resource busy`, потому что чипом владеет драйвер.

Тупиковый путь (не повторять): добавить `vbus-supply = <&usb_otg_vbus>;` в `&usb_dwc3`. Разница в DTB — ровно это
свойство (16 байт, проверено разбором обоих DTB), и планшет после этого висит на логотипе Lenovo: контроллер USB
вообще не пробуется. Откачено; рабочий образ — `boot-txmac2.img` (релиз v0.2).

Следующий шаг: включить dynamic debug для `tcpm` и `fusb302`, подключить/отключить устройство и посмотреть,
приходит ли вообще прерывание по CC. Если не приходит — проблема в прерывании FUSB302 (gpio97) или в разводке CC,
а не в TCPM.
